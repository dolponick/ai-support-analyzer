# Demo Video Script — AI Support Analyzer

### 0:00–0:15 — Intro

Привіт. Я виконав тестове завдання AI Support Analyzer. Це невеликий внутрішній інструмент для обробки звернень клієнтів.

Стек: Next.js, TypeScript, Supabase, Groq та GPT-OSS 20B.

### 0:15–0:45 — Create request

Відкриваю публічний Vercel-сайт і показую форму нового звернення. Тут вводяться імʼя клієнта і текст проблеми. Після збереження звернення потрапляє до черги та записується в Supabase.

### 0:45–1:20 — AI analysis

Натискаю «Аналізувати (AI)». Система повертає окремі поля: пріоритет, категорію, короткий підсумок і чернетку відповіді клієнту.

Результат має структурований формат, проходить повторну Zod-валідацію і зберігається в базі даних.

### 1:20–1:40 — Persistence

Оновлюю сторінку. Звернення та AI-аналіз залишаються на місці, тому що і сам запит, і результат аналізу збережені в Supabase.

### 1:40–2:05 — Code / architecture

Коротко показую analyze API route, strict JSON Schema для Groq, Zod-схеми та Supabase update. Усі привілейовані виклики виконуються лише на сервері.

### 2:05–2:30 — Real problem + solution

Під час QA я помітив, що модель інколи відповідала не тією мовою, якою було звернення. Я посилив інструкцію для LLM і додав явну мовну логіку, після чого повторно перевірив українські, англійські та російські кейси.

### 2:30–2:50 — AI coding workflow

Реалізацію робив через Codex поетапно: scaffold, база, UI, AI, UX, QA, GitHub і deploy. Після кожного етапу запускав lint, typecheck, build і runtime-тести.

### 2:50–3:00 — End

Результат задеплоєний на Vercel, а репозиторій опублікований на GitHub.
